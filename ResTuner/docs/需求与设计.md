## 3. 功能清单

### F1 目录定位
1. 读注册表 `HKLM\SOFTWARE\7-Zip` `InstallLocation`（含 WOW64 重定向回退）
2. 回退默认路径 `C:\Program Files\7-Zip`
3. 允许手动「浏览…」
4. 目录内必须同时存在 `7z.dll` 与 `7zFM.exe`，否则报错

### F2 目标体检（打补丁前必须完成）
- 文件类型：PE32+（`Magic == 0x20B`）；否则拒绝并说明
- 版本号：从 `RT_VERSION` 解析 `FileVersion` / `ProductVersion` / `CompanyName` / `OriginalFilename`
- 结构指纹（用于白名单与"是否已打过补丁"判断）：
  - 节区数量与名字序列
  - `RT_GROUP_ICON` 数量、每个组的资源名与条目数
  - `RT_BITMAP` ID 集合与各自宽高/位深
  - `RT_STRING` 内容 SHA-1（类型↔索引表）
- 已打补丁检测：`7z.dll` 的图标数量 ≫ 原始（如 218 vs 56）或 `RT_BITMAP` 内容等于主题素材 → 判定"已是主题版"

### F3 版本白名单
- 内置已验证版本表（初版只放 25.01），条目 = `版本号 + 7z.dll 结构指纹 + 7zFM.exe 结构指纹`
- 命中 → 直接执行
- 未命中 → 弹窗列出差异摘要，用户勾选「我知道风险，继续」后才执行（等价于 CLI 的 `--force`）
- 无论是否命中，都写入日志

### F4 执行前检查
- 目标文件是否可写（独占打开测试）；不可写 → 提示以管理员身份重启（GUI 用 `ShellExecuteW(runas)` 自提权）
- 进程占用：`7zFM.exe` / `7zG.exe` / `7z.exe` 是否在运行；是 → 提示关闭并提供「结束进程」按钮
- 是否存在 Authenticode 签名（`CERTIFICATE_TABLE`）：是 → 明确告知"改完签名失效"，并剥离签名表 + 同步 `SizeOfHeaders` 区域
- 磁盘剩余空间 ≥ 输出大小 × 2 + 64 MB

### F5 备份
```
<InstallDir>\.restuner-backup\<version>_<yyyyMMdd-HHmmss>\
    7z.dll   7zFM.exe   manifest.json
```
`manifest.json`：时间、版本、原文件 SHA-256/大小、工具版本、主题包名。
保留最近 N=10 份，超出提示可清理（不自动删）。

### F6 打补丁

**7zFM.exe —— 等尺寸原地覆盖**
| 资源 | 尺寸 | 素材 |
|---|---|---|
| `RT_BITMAP` 100…106 | 48×36 / 4bpp / 968 B | `assets\toolbar\48x36\{Add,Extract,Test,Copy,Move,Delete,Info}.bmp` |
| `RT_BITMAP` 150…156 | 24×24 / 4bpp / 392 B | `assets\toolbar\24x24\…` |

- 写入内容 = `.bmp` 去掉 14 字节 `BITMAPFILEHEADER`
- 逐项校验：位深/调色板/`biSizeImage`/尺寸必须与目标一致，否则该项跳过并报"素材不兼容"
- 因长度相同 → **不重建 .rsrc**，仅重算 `CheckSum`（这是对现有补丁的改进：diff 从 35,763 字节降到 ~1.4 万字节且不改结构）
- `RT_GROUP_ICON` #100、`RT_VERSION`：**原样保留**（修缺陷 ① ②）

**7z.dll —— 资源重建**
1. 读 `RT_STRING` → `扩展名:索引` 表（如 `7z:0 zip:1 …`）
2. 对表中每个索引：`assets\filetype\<ext>.ico`；无该文件则按别名表回退
   （`txz→xz`、`tbz2/tbz→bz2`、`taz→z`、`tgz/tpz→gz`、`lha→lzh`、`esd/swm→wim`、`vhdx→vhd`、`tzst→zst`）
3. 解析 `.ico` → 每个尺寸一条 `RT_ICON` + 重建一份 `GRPICONDIR`
   - 宽/高一律**从图像数据本身推导**（PNG 用 `IHDR`，DIB 用 `biWidth/biHeight/2`），不信任 ICO 目录项 → 修缺陷 ① 的同类问题
   - 256×256 的 `bWidth/bHeight` 按规范写 `0`
4. **删除** 被替换组的全部旧 `RT_ICON`（含 arj 的 11/12 → 修缺陷 ③）
5. 新 `RT_ICON` ID 从"当前最大 ID + 1"开始连续分配（不硬编码 57…272）
6. 重建 `.rsrc` 节区

> 若某索引没有素材 → 该组完全不动（保留官方原图标），日志标记 `SKIP`。
> 绝不产出"删了旧图标却没放新图标"的半成品。

### F7 `.rsrc` 重建算法（核心）
1. 收集最终资源集合（类型 → 名称 → 语言 → 数据）
2. 规范化排序：类型升序（字符串名排在数字 ID 前）→ 名称升序（同上）→ 语言升序
3. 布局新节区（全部按 4 字节对齐，字符串节按 2 字节）：
   `目录表 → 各层子目录 → 名称字符串 → 数据项(16B) → 资源数据块`
4. 计算 `VirtualSize`，`RawSize = align(vsize, FileAlignment)`
5. 若 `.rsrc` 后面还有节区：按新尺寸顺移其 `VirtualAddress` / `PointerToRawData`；
   并修正所有**落在被移动节区内**的数据目录 RVA（`BASERELOC` / `EXCEPTION` / `DEBUG` / `IMPORT` / `IAT` / `LOADCFG` / `DELAYIMP` / `TLS` …）
6. 同步头部字段：

| 字段 | 处理 |
|---|---|
| `.rsrc.VirtualSize` / `RawSize` | 重算 |
| `SizeOfImage` | `align(末节.VirtualAddress + max(VirtualSize, RawSize), SectionAlignment)` |
| `SizeOfInitializedData` | 原值 + (新 `.rsrc.RawSize` − 旧 `.rsrc.RawSize`) |
| `RESOURCE` 目录 (RVA, Size) | `(.rsrc.RVA, .rsrc.VirtualSize)` |
| 被移动节区的数据目录 | RVA 按位移量修正 |
| `CheckSum` | 按 PE 规范重算（含此字段本身） |
| `CERTIFICATE_TABLE` | 若存在签名：置 0 并说明（签名必然失效） |

7. 保留文件尾部 overlay（若非签名数据）

### F8 自检（写回前，硬门槛）
- 重新解析产出文件：`PE32+`、节区数一致、节区不重叠、`SizeOfImage` 合法
- 资源键集合与「预期集合」完全一致（无多、无少）
- 每个被替换资源的 SHA-1 与素材推导值一致
- 反向验证：未参与替换的资源内容 SHA-1 与输入**逐一相同**
- 调试期间附加：`subprocess` 调 `7z.exe i` 能正常退出（0），`7zFM.exe` 能被 `LoadLibrary`/启动
- 任一项失败 → 删除临时文件，报错，原文件不动

### F9 写回
写入同目录临时文件 → 自检 → `os.replace()` 原子替换；异常回滚到备份。
结束后可选「刷新图标缓存」（`ie4uinit.exe -show`）+ 提示「重启资源管理器/注销后生效」。

### F10 还原
列出 `.restuner-backup\*`，选一份 → 覆盖回 → 校验 SHA-256 与 manifest 一致。

### F11 日志
界面逐项输出 + 落盘 `logs\restuner_<yyyyMMdd-HHmmss>.log`（UTF-8）。

## 5. 工程结构（在现有 ResTuner 项目中重写）

```
ResTuner/
  src/
    restuner/
      __init__.py
      pe.py            PE 头/节表/数据目录 读写
      rsrc.py          资源树解析 + .rsrc 重建
      icon.py          .ico → RT_ICON/GRPICONDIR（宽高从图像推导）
      bmp.py           .bmp 去文件头 + 兼容性校验
      checksum.py      PE CheckSum
      theme.py         主题包（filetype/toolbar 素材 + 别名表）
      target.py        目标检出/体检/指纹/白名单
      patcher.py       规则编排：7zFM 原地覆盖、7z.dll 重建
      verify.py        自检 + 资源级比对
      backup.py        备份/还原
      logbus.py        线程安全日志
      errors.py        异常类型
    gui/
      app.py           tkinter 主窗口
      widgets.py       可复用控件
  assets/              现有素材（不动）
  tests/
    test_pe.py  test_rsrc.py  test_icon.py  test_patcher.py
    test_accept_2501.py   与 patches\7z2501-x64-patch 做资源级比对
  tools/
    dump_res.py        资源树打印（调试/对照用）
    verify_parity.py   资源级等价校验脚本
  run_gui.bat
```

技术约束：
- **零第三方依赖**，只用标准库（`tkinter` / `struct` / `hashlib` / `json` / `subprocess` / `winreg`）
- 兼容 **Python 3.9+**（你 PATH 上是 3.9.12）；不用 `match`、不用 `X | Y` 运行期类型
- 保留 `assets/`、`examples/` 不动；旧的 `src/core`、`src/cli` 在确认后删除（或移到 `_legacy/`）

## 6. 验收标准（可自动执行）

| 编号 | 用例 | 判据 |
|---|---|---|
| A1 | 对 `assets\7z2501-x64` 跑一遍 | 与 `patches\7z2501-x64-patch` **资源级等价**：资源键集合相同；每个资源的 SHA-1 相同；仅允许 3 处已修复差异（GROUP_ICON#100 宽高、RT_VERSION 保持原样、arj 组不再残留 11/12） |
| A2 | 产出可用性 | `7z.exe i` 退出码 0；`7zFM.exe` 能启动且工具栏/图标正确（人工确认一次） |
| A3 | 还原 | 还原后两文件 SHA-256 与备份完全一致 |
| A4 | 幂等 | 对已打补丁的文件再跑 → 提示"已是主题版"，不重复处理 |
| A5 | 负向 | 32 位 PE / 非 PE / 文件缺失 / 目录只读 / 文件被占用 → 明确报错，目标文件字节不变 |
| A6 | 资源完整性 | 7zFM 的 74 个未涉及资源、7z.dll 的 `RT_STRING`/`RT_VERSION` 逐字节不变 |

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| `.rsrc` 重建算错 → 文件损坏 | 写回前强制自检 + 临时文件 + 原子替换 + 备份回滚 |
| 未来版本结构变化（新增格式/ID 变动） | 结构自适应 + 逐项 SKIP 报告 + 白名单校验后才放行 |
| 官方开始签名 | 检测 `CERTIFICATE_TABLE` → 告知并剥离；日志留痕 |
| Program Files 权限 | 自动提权 + 可写性预检 |
| 图标缓存导致"看着没生效" | 内置刷新动作 + 明确提示 |
