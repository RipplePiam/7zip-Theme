# 7-Zip 26.05 复核记录

> 目的：确认"结构自适应"在比 25.01 更新的官方版本上依然成立，并把 26.05 纳入已验证清单。

## 素材来源

用户机器上的一份**官方原版备份**（由 ResTuner 自己打补丁前自动生成）：

```
C:\Program Files\7-Zip\.restuner-backup\26.05_20261101-224011\
├─ 7z.dll      1,908,736 B  SHA256 78BF6B66…8DFABB82
├─ 7zFM.exe    1,003,520 B  SHA256 E036AB15…16C1EAEE
└─ manifest.json            （tool=ResTuner 1.0.0 / version=26.05 / created=2026-11-01T22:40:11）
```

构建时间戳：`2026-10-21 20:00`；`FileVersion = 26.05`；`CheckSum = 0`（官方发布不带校验和，符合预期）。

## 结构对照

| 项 | 25.01 | 26.05 |
|---|---|---|
| PE 类型 | PE32+ (x64) | PE32+ (x64) |
| 节区 | `.text .rdata .data .pdata .rsrc .reloc` | 同 |
| `7z.dll` 资源总数 | 85 | 85 |
| `7z.dll` RT_ICON | 56 | 56 |
| `7z.dll` RT_GROUP_ICON | 27（每组 2 项，`"0"` 组 4 项） | 同 |
| 类型索引表 SHA-1 | `59592a87…73d3dc11` | **完全相同** |
| `7zFM.exe` RT_BITMAP | 100–106 / 150–156 / 190 | 同 |
| `SizeOfImage`（dll / exe） | `0x1E1000` / `0xF9000` | `0x1E2000` / `0xFA000` |

结论：**资源层面的结构一字未变**，只是代码段变大了一点。所以图标索引映射（来自 `RT_STRING`）
和工具栏位图 ID 都不需要任何调整，素材零缺口（27 个索引全部有对应 `.ico`）。

## 逐字节复现

拿上表的官方原版当输入，用当前引擎重新打一次主题，与用户机器上**已安装的那份**对比：

| 文件 | 引擎产出 | 已安装 | 逐字节一致 |
|---|---|---|---|
| `7z.dll` | 3,480,064 B | 3,480,064 B | **是** |
| `7zFM.exe` | 1,003,520 B | 1,003,520 B | **是** |

两次独立运行（用户那次 + 本次复算）产出一模一样，说明：

1. 引擎是**确定性**的（同样的输入 + 同样的素材 → 同样的输出）；
2. 用户机器上那份确实是本工具的作品，没有额外改动；
3. 自适应路径在 26.05 上产出的结果与在 25.01 上一样正确。

edit 摘要也与 25.01 一致：

```
7z.dll    mode=rebuild  +216 -56 ~27  rsrc_growth=+1571020  moved=.reloc
7zFM.exe  mode=inplace  +0   -0  ~14  rsrc_growth=+0
```

## 运行期验证

```
结构自检（节区/对齐/SizeOfImage/校验和）           OK
LoadLibrary(已安装 7z.dll)                        OK
7z.exe i                                          → 7-Zip 26.05 (x64) 2026-10-21
工具栏位图 5/5 抽查 == 主题素材                    一致
```

## 结论

26.05 已加入 `VERIFIED_VERSIONS`，与 25.01 共用同一份结构指纹
（`dll_group_count=27` / `dll_icon_count=56` / `fm_bitmap_ids=(100…190)` / 类型表 SHA-1）。

顺带把指纹校验做成了**实际生效**的检查：版本号命中但结构不符时会降级为"结构指纹不符"，
仍然需要用户勾选「我知道风险」才继续 —— 防止有人把非官方重构版误当成验证过的版本。
